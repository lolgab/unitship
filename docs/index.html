unitship

Deploy SNUnit and FreeUnit apps to your own server. Zero-downtime releases, HTTPS, rollbacks, a web panel. One user, systemd, no Docker.

GitHub Releases Full README

Install

curl -fsSL https://lolgab.github.io/unitship/install.sh | bash
unitship --version

Linux x86_64 and macOS arm64 binaries are on the releases page. Other platforms: build from source with scalino package vendor src -o unitship.

Quickstart

# on the server, once (see the README for the root steps)
unitship setup --email you@example.com --base-domain apps.example.com

# from your machine
unitship --host me@my-server create blog
unitship --host me@my-server deploy blog ./blog      # executable built with `snunit package`
unitship --host me@my-server tls blog                # Let's Encrypt

How it works

  • An SNUnit app is one executable that embeds its own unitd. Each release is a systemd user service on 127.0.0.1:$PORT.
  • An edge FreeUnit on ports 80/443 routes by Host to the active release and terminates TLS.
  • A deploy starts the new release, waits until healthy, atomically switches the edge, then stops the old one. If the new release fails, nothing changes.
  • State is plain files in ~/.unitship. Remote commands run over ssh; no other protocol.

Your app

//> using dep com.github.lolgab::snunit::0.13.0
import snunit.*
import snunit.config.*

@main
def run =
  val address = s"${sys.env.getOrElse("BIND_ADDRESS", "*")}:${sys.env.getOrElse("PORT", "8080")}"
  SyncServerBuilder
    .setConfig(UnitConfig(listeners = Seq(Listener(address))))
    .setRequestHandler(req => req.send(StatusCode.OK, "Hello world!\n", Headers.empty))
    .build()
    .listen()

Limits

One server. Isolation is that of a Unix user: don't host untrusted code. No bundled databases. HTTP/1.1 only. See the README.
